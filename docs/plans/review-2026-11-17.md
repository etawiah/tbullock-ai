# Code review: Tom Bullock / Purple Moonz home-bar app (2026-11-17)

**Status:** Phase 1 (audit) complete. Phase 2 (fixes) is waiting for approval.
**Scope:** all code (`src/`, `worker/worker.js`, `barmenu-public/`, `public/`, `scripts/`), config (`package.json`, `wrangler.toml`, `vite.config.js`, `index.html`), the root docs, the live site (status codes only) and the deployed Worker (read-only, through the connected Cloudflare account).

## Notes on the brief

The review brief was written for a different (workout-tracking) app, so I adapted it:

* **No AGENTS.md, no `docs/` folder, no `js/app.js`, no `_headers`, no `/api/reset.js`, no D1.** This app is a React SPA (`src/App.jsx`, 4,112 lines) plus one Cloudflare Worker (`worker/worker.js`) that stores everything in **Workers KV**. A KV "schema change" here means adding keys or changing the shape of stored JSON.
* **`npm test` and `npm run smoke` don't exist.** There are no tests of any kind. `npm run build` passes (232 KB JS, 66 KB gzipped).
* Workout terms were mapped to bar terms: "log a set" became "log a pour/drink", "workout history" became inventory, favorites, shopping list and chat history, and "in the gym" became "at the bar on phone Wi-Fi/cellular". A rest timer and its notifications don't apply here, so they were skipped.

## How this was tested

* Read every source file and config file.
* `npm install`, `npm run build` and `npm audit` (4 advisories, all in dev or script-only packages).
* **Playwright, iPhone 13 emulation:** a harness served the production build and routed API calls to the **real `worker/worker.js`**, running in-process against an in-memory KV seeded with `initial-inventory.json` and `initial-recipes.json`, with a fake Gemini. It drove chat, inventory, add bottle, make drink, the bottle picker, delete favorite, the menu editor, dark mode, offline, and a simulated KV read failure, then ran axe-core (WCAG 2 A/AA) and a tap-target scan on each tab.
* **Live checks (status codes only, no data read):**
  * `bartender-api.eugene-tawiah.workers.dev` returns Cloudflare error **1042** (no Worker is serving the workers.dev route).
  * `bartender.tawiah.net` returns a 302 to Cloudflare Access.
  * On `barmenu.tawiah.net/api/*`, only `GET /api/menu` returns 200. Every other route returns 403.
* Deployed Worker source was fetched read-only and compared with the repo.

Screenshots are in [`review-2026-11-17/`](review-2026-11-17/).

## Findings

Severity: **Critical** means data loss, a security exposure or the app becoming unusable. **High** means a frequent wrong result or lost user action. **Med** means real but limited or rare. **Low** is polish.
Confidence: **Verified** means reproduced in the harness or on the live site. **Code** means certain from reading the code but not reproduced. **Likely** is an inference.

## Top 10 I recommend, in order

1. **C3 + H9: stop failed loads from overwriting data.** This is the only path where you silently lose your real inventory, chat or shopping list. It's small and safe.
2. **C4 (+ error boundary): fix the white screen on "Make This Drink".** It's the core action of the app, it breaks whenever you own two similar bottles, and the fix is one line plus a safety net.
3. **H1 + H2: make −Shot, "+ Add bottle" and import actually save.** These are the fastest ways to log a pour or a bottle, and today they quietly throw the work away.
4. **H5: deleting favorites.** Small fix for a visible bug.
5. **C2 + M1: lock down the API and escape the guest menu.** These turn a hidden landmine (the next `wrangler deploy`) into a non-event. C2's config line needs your OK.
6. **C1: reconcile the repo with production.** Until this is done, deploying from git breaks the app. I need you to confirm how `/api` is routed today.
7. **H3: chat inventory updates.** The AI currently tells you it updated inventory when it didn't, which is worse than not offering the feature.
8. **H4: two-phone overwrite guard.** You both use it, and this is how bottles "disappear". Needs your OK because it adds a stored revision.
9. **H8: daily backups + Export everything.** A cheap insurance policy given everything above. Needs your OK because it adds KV keys.
10. **H7 + H6 + M6 + M7 (mobile polish batch):** unblock the Menu tab, make dark mode readable, cut the 1.6 MB logo, and fix zoom, labels, contrast and tap sizes. Each is small, and together they're the biggest everyday-feel improvement.

Alongside these I'd add `npm test` (Node built-in runner, no new dependency) and regression tests for each fix (M9).
